# План разработки (Roadmap)

В данном документе перечислены приоритетные задачи по развитию Storage Service, основанные на текущей архитектуре и обсужденных улучшениях.

## 1. Публичные бакеты и "вечные" ссылки [ ]

- [ ] **Добавить поле `is_public` в таблицу `storage.buckets`**
  - _Зачем:_ Чтобы явно разделять приватные хранилища и те, файлы из которых могут быть доступны без авторизации.
- [ ] **Настроить Row-Level Security (RLS) в Hasura для роли `anonymous`**
  - _Зачем:_ Ограничить анонимный доступ только теми файлами, которые находятся в бакетах с флагом `is_public: true`.
- [ ] **Обновить `FilesService` и `FilesController`**
  - _Зачем:_ Чтобы бэкенд учитывал флаг публичности при валидации запросов и мог возвращать информацию о доступности файла.

## 2. Синхронизация политик MinIO через Event Triggers [ ]

- [ ] **Реализовать Webhook-эндпоинт в NestJS**
  - _Зачем:_ Для приема уведомлений от Hasura при изменении метаданных бакета (например, переключение `is_public`).
- [ ] **Добавить метод `setBucketPolicy` в `MinioService`**
  - _Зачем:_ Чтобы автоматически менять права доступа на стороне S3 (MinIO). Если бакет становится публичным, MinIO разрешит прямые GET-запросы к объектам.
- [ ] **Настроить Event Trigger в Hasura**
  - _Зачем:_ Чтобы база данных сама "дергала" бэкенд при каждом обновлении таблицы бакетов.

## 3. Улучшение аутентификации [ ]

- [ ] **Поддержка `HASURA_GRAPHQL_ADMIN_SECRET` как Service Token**

  - _Зачем:_ Позволить внутренним сервисам обращаться к хранилищу, используя уже существующий админ-секрет Hasura (через заголовок `x-hasura-admin-secret`). Это упрощает интеграцию и избавляет от необходимости плодить новые ключи.
  - _Пример реализации в `AuthGuard`:_

    ```typescript
    const adminSecret = this.configService.get("HASURA_GRAPHQL_ADMIN_SECRET");
    const requestAdminSecret = request.headers["x-hasura-admin-secret"];

    if (adminSecret && requestAdminSecret === adminSecret) {
      request.hasuraUserId = "admin"; // Системный ID
      request.hasuraRoles = ["admin"];
      return true;
    }
    ```

## 4. Расширение возможностей API [ ]

- [ ] **Генерация прямых S3-ссылок**
  - _Зачем:_ Для публичных бакетов API должен уметь возвращать прямую ссылку на MinIO (в обход бэкенда), чтобы снизить нагрузку на NestJS при раздаче тяжелого контента.
- [ ] **Поддержка папок (префиксов)**
  - _Зачем:_ Сейчас файлы лежат "плоским" списком в бакете. Нужно добавить поддержку виртуальных папок для лучшей организации пространства.

## 5. SDK и клиентская часть [ ]

- [ ] **Обновить SDK для поддержки публичного доступа**
  - _Зачем:_ Добавить методы для проверки, является ли файл публичным, и получения соответствующих ссылок.
- [ ] **Добавить поддержку загрузки по частям (Multipart Upload) в SDK**
  - _Зачем:_ Для стабильной загрузки очень больших файлов (от 100МБ и выше).

## 6. Разработка универсального SDK [ ]

- [ ] **Создание Isomorphic SDK (Frontend + Backend)**
  - _Зачем:_ Нужна единая библиотека, которая упростит работу с сервисом.
  - _Frontend:_ Автоматическая обработка сессионных кук, методы для `upload` (с прогресс-баром) и `download`.
  - _Backend:_ Методы для серверных операций, поддержка авторизации через Service Token или проброс заголовков пользователя.
- [ ] **Типизация (TypeScript)**
  - _Зачем:_ Предоставить готовые интерфейсы для метаданных файлов и бакетов, чтобы избежать ошибок при интеграции.

## 7. Интеграция в существующую экосистему [ ]

- [ ] **Инструкция по подключению через Hasura Remote Schemas**
  - _Зачем:_ Если в основном проекте уже есть Hasura, Storage Service можно подключить как Remote Schema. Это позволит делать Join-запросы (например, получить аватар пользователя одним запросом вместе с данными профиля).
- [ ] **Конфигурация Shared Auth (Better Auth)**
  - _Зачем:_ Описать, как настроить `crossSubDomainCookies` в Better Auth, чтобы сессия была единой для основного приложения и сервиса хранения.
- [ ] **Миграция на общую БД (Shared Schema)**
  - _Зачем:_ Storage Service спроектирован для работы в отдельной схеме `storage`. Это позволяет легко "подселить" его в существующую БД проекта, не создавая лишних инстансов Postgres.
