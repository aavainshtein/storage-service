# План разработки (Roadmap)

В данном документе перечислены приоритетные задачи по развитию Storage Service в порядке их важности для реализации.

## 1. Поддержка `HASURA_GRAPHQL_ADMIN_SECRET` как Service Token [ ]

- [ ] **Реализация в `AuthGuard`**

  - _Зачем:_ Позволить бэкенду других проектов и скриптам обращаться к хранилищу напрямую, используя уже существующий админ-секрет Hasura. Это приоритетная задача для обеспечения взаимодействия "сервис-сервис".
  - _Пример реализации:_

    ```typescript
    const adminSecret = this.configService.get("HASURA_GRAPHQL_ADMIN_SECRET");
    const requestAdminSecret = request.headers["x-hasura-admin-secret"];

    if (adminSecret && requestAdminSecret === adminSecret) {
      request.hasuraUserId = "admin";
      request.hasuraRoles = ["admin"];
      return true;
    }
    ```

## 2. Разработка универсального Isomorphic SDK [ ]

- [ ] **Единый интерфейс для всех сред (Browser + Node.js)**
  - _Зачем:_ Чтобы разработчик использовал один и тот же код везде. SDK должен автоматически определять среду выполнения для корректной работы с файлами (Blob/File в браузере vs Buffer/Stream в Node) и авторизацией.
- [ ] **Полный набор методов:**
  - `upload(file, options)`: Загрузка с автоматическим формированием метаданных.
  - `download(fileId)`: Получение потока данных или ссылки.
  - `delete(fileId)`: Удаление файла.
  - `getMetadata(fileId)`: Получение информации о файле из Hasura.
  - `getPresignedUrl(fileId, expiry)`: Генерация временной ссылки.
  - `listBuckets()`: Просмотр доступных бакетов.
- [ ] **Поддержка прогресса загрузки:** Встроенный коллбэк `onProgress` для отображения статуса на фронтенде.
- [ ] **Типизация (TypeScript):** Полная поддержка типов для всех ответов API и метаданных.

## 3. Интеграция и развертывание (Shared Schema) [ ]

- [ ] **Инструкция по "подселению" в существующий проект**
  - _Зачем:_ Вместо сложной настройки Remote Schemas, на данном этапе проще использовать общую БД.
  - _Шаги:_
    1. Накат миграций схемы `storage` в основную БД проекта.
    2. "Трекинг" (Track Tables) таблиц схемы `storage` в основной Hasura проекта.
    3. Настройка Relationships между основными таблицами (например, `users`) и таблицей `storage.files`.
- [ ] **Конфигурация Shared Auth:** Инструкция по настройке единого домена для кук в Better Auth.

## 4. Публичные бакеты и "вечные" ссылки [ ]

- [ ] **Добавить поле `is_public` в таблицу `storage.buckets`**
  - _Зачем:_ Разделение приватных и публичных хранилищ.
- [ ] **Настройка RLS в Hasura для роли `anonymous`**
  - _Зачем:_ Разрешить скачивание файлов без авторизации только из бакетов, помеченных как `is_public`.
- [ ] **Генерация прямых S3-ссылок:** Возможность получения ссылки напрямую на MinIO для публичных файлов.

## 5. Синхронизация и отказоустойчивость [ ]

- [ ] **Синхронизация политик MinIO через Event Triggers**
  - _Зачем:_ Автоматическое изменение прав доступа в MinIO при смене флага `is_public` в Hasura.
- [ ] **Проработка механизмов гарантированной доставки:** Решение проблемы рассинхрона при сбоях сети или перезагрузках сервиса.
